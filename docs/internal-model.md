# Внутренняя модель статьи, версия 1

Формальное описание — `schemas/analysis.schema.json` (JSON Schema 2020-12).
Модель представляет результат разбора **до генерации словоформ**.
JSON-представление используется для эталонов и рабочего результата.
Python-интерфейс возвращает обычные словари и списки в этой структуре. Названия полей не повторяют сокращения ADB,
но различия исходной модели сохраняются.

## Результат одной статьи

| Поле | Назначение |
|---|---|
| `schema_version` | Версия модели, сейчас 1 |
| `source_index` | Позиция объекта в текущем входе, от 0 |
| `source` | Исходный объект без изменения строк |
| `effective_lemma` | Заглавная строка после наследования; `null`, если определить нельзя |
| `inherited_from` | Индекс явно заданной леммы либо `null` |
| `headword` | Нормализованное написание и варианты ударения; `null` при невалидном входе |
| `status` | `parsed`, `needs_reference`, `unsupported`, `invalid` |
| `readings` | Независимые грамматические разборы внутри одной статьи |
| `annotations` | Значения, регистр, условия употребления, примеры, фразеологизмы |
| `unparsed` | Необработанные фрагменты, запрещающие успешный разбор |
| `diagnostics` | Структурированные коды и понятные русские сообщения |

Статус `parsed` означает, что описание представлено моделью полностью, без
необработанного остатка и неразрешённых зависимостей. `needs_reference` означает,
что отсылка распознана, но отсутствует или неоднозначен образец. Разбор уже
известных фрагментов сохраняется и при `unsupported`, но не считается полной
инструкцией к генерации.

Для одной статьи может быть несколько `readings`: в «столько» с символом `н;`
сохраняются и наречие, и числительное. Это не варианты ударения и не омонимы
из других объектов массива.

## Написание и ударения

```json
{
  "text": "столитровый",
  "accent_variants": [
    {"primary": [8], "secondary": [3], "basis": "explicit"}
  ]
}
```

`primary` содержит одновременные основные ударения. `secondary` — побочные.
Несколько элементов `accent_variants` — альтернативные произношения.
`basis`: `explicit`, `yo`, `monosyllabic`, `unstressed`, `missing`.
Нулевые позиции не используются. У безударного слова — пустой `primary` и
`unstressed`; у недостаточно описанного — пустой `primary` и `missing`.
Эти состояния нельзя смешивать.

## Грамматический разбор

| Поле | Смысл |
|---|---|
| `part_of_speech` | `noun`, `adjective`, `verb`, `adverb`, `pronoun`, `numeral`, `surname` |
| `gender` | Лексический род либо `null`, если не задан или неприменим |
| `agreement_genders` | Для каких родов нужны формы: у прилагательного м/ж/с, у фамилии м/ж |
| `animacy` | `animate`, `inanimate`, `unspecified`, `not_applicable` |
| `number_scope` | `both`, `plural_only`, `unspecified`, `not_applicable` |
| `inflection` | Правила изменения слова или способ получения форм |
| `verb` | Вид, переходность, возвратность, видовой партнёр; иначе `null` |
| `deviations` | Номера отклонений и признак факультативности |
| `restrictions` | Ограничения на выбранные грамматические формы |
| `explicit_forms` | Полностью восстановленные формы, выписанные в статье |
| `relations` | Равенство форм, например В. неод. = И. |
| `reference` | Отсылка к другому описанию либо `null` |

Фамилия выделяется отдельным видом разбора: символ `ф.` не нужно автоматически
приравнивать к существительному мужского рода. У «Столетов» сохраняется
потребность в мужском и женском вариантах. На этапе разбора женская исходная
форма не вычисляется — это задача генератора.

Лексический род и признаки образца склонения различаются. У «столище»
`gender = masculine`, а `inflection.pattern_gender = neuter`. У «столяришка»
лексический род мужской, образец женский и одушевлённый. У `мн. <м 5*b>`
лексический род не приписывается автоматически: задан род образца и
`number_scope = plural_only`.

## Правила словоизменения

`inflection` содержит:

- `kind`: `regular`, `explicit`, `invariable`, `reference`;
- `family`: `substantive`, `adjectival`, `pronominal`, `verbal`, `explicit`, `none`;
- `pattern_gender`, `pattern_animacy`: признаки явно указанного образца;
- `index`: номер типа либо `null`, если он не задан;
- `fleeting_vowel`: звёздочка при номере;
- `special_alternation`: кружочек при номере;
- `consonant_alternation`: указание вроде `(-с-)`;
- `stress.full`, `stress.short`, `stress.past`: схемы ударения.

`null` для схемы означает «в статье не указана», а не автоматическое `a`.
Правила наследования схем кратких и прошедших форм переносятся из оригинала
на этапе генерации. Неподвижность ударения не выводится из одной леммы.

У отсылки номер типа остаётся `null`. Отсутствие локальных звёздочек и других
маркеров не отменяет соответствующие признаки ещё не разрешённого образца.

## Глагольные сведения

`verb.aspect`: `perfective`, `imperfective`, `biaspectual`.
`transitivity`: `transitive`, `intransitive`, `unknown`.
`transitivity_basis` фиксирует основание: явное `нп`, возвратность,
словарное значение по умолчанию либо отсутствие данных.

В обычной индексированной глагольной статье отсутствие `нп` и возвратного
постфикса трактуется по соглашению словаря как переходность. Это не попытка
определить переходность по написанию глагола.

`partner` хранит направление видовой пары, тип, указание замены и исходный текст.
Например, `◑I(-а́-)` не становится согласным чередованием текущего глагола.
Построение видового партнёра и построение словоформ исходного глагола —
разные операции, использующие эти сведения.

## Ограничения и выписанные формы

Грамматические признаки имеют именованные поля: `case`, `number`, `gender`,
`animacy`, `form`, `tense`, `person`, `voice`. Используется только нужное подмножество.

```json
{
  "selector": {"form": "short", "gender": "masculine"},
  "status": "absent",
  "note": "⌧"
}
```

Ограничения не уничтожают другие разборы той же статьи. При пересечении действует
более конкретное ограничение; например, ⌧ задаёт затруднительность кратких форм,
но отсутствие именно краткой формы мужского рода.

`explicit_forms` содержит восстановленное слово, его ударение, грамматические
признаки, статус и примечание. Запись `сто́льк|их, Д. -им` становится «стольких»
и «стольким» с ударением на позиции 3. Символ `|` и сокращение `-им` не должны
попасть в текст готовой формы.

`relations` задаёт совпадение форм через признаки. Например, у числительного
«столько» В. одуш. имеет два источника: Р. или И. У местоимения из следующей
статьи выписаны другие косвенные формы. Смешивать их нельзя.

## Связь с ADB оригинала

| ADB | Новая модель |
|---|---|
| `с`, `у` | `headword.text`, `headword.accent_variants` |
| `т`, `т2` | `part_of_speech`, `inflection.family` |
| `р`, `рм` | `gender`, `inflection.pattern_gender` |
| `о`, `мн` | `animacy`, `number_scope` |
| `и`, `у1`, `у2` | `inflection.index`, `inflection.stress` |
| `ч`, `ч2`, `ч3` | Беглая гласная, особое и согласное чередования |
| `ос`, `осф` | `deviations` |
| `фн`, `фз`, `фп` | `restrictions` и статусы форм |
| `искл` | `explicit_forms`, `relations` и правила восстановления исключений |
| `гпр` | `verb.partner` |
| `з`, `фр` | `annotations` |

Это соответствие смыслов, а не побайтовое преобразование ADB. Неизвестные
конструкции сохраняются как `unsupported`; известные, но ещё не поддержанные
механизмы блокируют генерацию отдельно.


## Рабочие модули

- `zaliz/model.py` — конструкторы модели и типы ошибок.
- `zaliz/text.py` — форматирующая разметка, пояснения, Unicode и ударения.
- `zaliz/parser.py` — грамматические описания, ограничения и выписанные формы.
- `zaliz/references.py` — зависимости внутри группы, разрешение и диагностика.
- `zaliz/__init__.py` — `analyze`, валидация объектов, наследование леммы.
- `zaliz/__main__.py` — файловый интерфейс и stdin/stdout.

При успешной отсылке `reference.resolution = resolved`, а `source_index`
указывает на запись-образец в том же результате. Локальный номер типа
остаётся `null`: правила образца не копируются и не выдаются за собственные
указания исходной статьи. Генератор применяет совместимый образец при замене начальной части слова;
неоднозначный способ переноса диагностируется отдельно.

Выписанные формы упорядочиваются по падежам И., Р., Д., В., Т., П.; варианты
внутри одного падежа сохраняют исходный порядок. Две пометы после одной
выписанной формы («Р., П.») разворачиваются в две отдельные позиции.


## Дополнения для именного склонения

Необязательное поле `inflection.yo_alternation` появляется при явной помете `ё`
и означает чередование е/ё. Отсутствие поля не подменяется догадкой по лемме.
Прежние 77 эталонов анализа не изменены. Независимые ожидания новых случаев —
`tests/fixtures/declension-parse.expected.json`.

Вторая схема ударения в образце `<п 1a/c>` сохраняется и у существительного.
Это свойство образца; краткие формы самого существительного не создаются.

Результат генерации добавляется отдельным полем `generation`, не изменяя
структуру исходного разбора. См. [generation.md](generation.md).


## Дополнения для спряжения

Схема `inflection.stress.full` задаёт ударение личных форм, `past` — прошедшего
времени. При отсутствии второй схемы применяется исходное правило `a` для
прошедшего; первая схема не переносится в прошедшее автоматически.

Помета `безл.` превращается в ограничения: отсутствуют личные формы 1/2 лица
и множественного числа, прошедшее мужского/женского рода, императив, причастия
и деепричастия. Доступны инфинитив, 3 лицо ед. числа и прошедшее среднего рода
при допустимом времени. Новые обязательные поля в модель не добавляются.

У результата генерации причастие имеет `form: participle`, `voice` и `tense`.
Полные формы дополнительно имеют `case`, краткие — `number` и при необходимости
`gender`, без `case`. Сравнительная степень причастиям не создаётся.


## Дополнения четвёртого рабочего этапа

Необязательные поля `inflection.extra_cases`, `paragraphs`, `alternatives`
сохраняют П2/Р2, номера дополнительных параграфов и альтернативные глагольные
индексы. Прежние 77 эталонов остаются без изменений. `explicit_forms` в регулярной
статье теперь содержит исключения для отдельных позиций; в `kind: explicit`
это по-прежнему полный выписанный перечень форм.

Видовой партнёр сохраняется в `verb.partner` на стадии анализа. Его результат
добавляется в `generation.readings[i].aspect_partner`, а не в `forms`. Ошибка
партнёра не уничтожает готовую парадигму, но делает общий статус `partial`.
Форматы, примеры и ограничения: [special.md](special.md).
