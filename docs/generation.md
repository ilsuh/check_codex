# Генерация словоформ

Реализованы именное склонение и третий рабочий этап — глагольные основы,
спряжение и склонение причастий. В подробном плане это пункты 3 и 4,
после спецификации и парсера. Исключения, дополнительные падежи, образцы и
видовые партнёры добавлены четвёртым рабочим этапом: [special.md](special.md).

## Интерфейсы

```sh
python3 -m zaliz --generate examples/single.json
python3 -m zaliz --generate examples/group.json -o forms.json
```

Без `--generate` командная строка по-прежнему возвращает только разбор.
Формат исходного JSON не меняется: один объект или массив.

```python
from zaliz import analyze, generate, generate_analyzed

source = {"lemma": "столбе́ц", "symbol": "м", "grammar": "5*b"}
results = generate(source)
forms = results[0]["generation"]["readings"][0]["forms"]
print([form["stressed"] for form in forms])

# Использование уже разобранной модели без повторного разбора:
assert generate_analyzed(analyze(source)) == results
```

`generate_analyzed` принимает список результатов `analyze` в согласованной
модели. Обе функции сохраняют исходные данные и не изменяют переданный объект.

## Что добавляется в результат

Все поля результата анализа сохраняются. Добавляется `generation`:

```json
{
  "status": "generated",
  "readings": [{
    "reading_index": 0,
    "status": "generated",
    "forms": [{
      "features": {
        "case": "genitive",
        "number": "singular",
        "gender": "masculine"
      },
      "word": {
        "text": "столбца",
        "accent_variants": [{"primary": [7], "secondary": [], "basis": "explicit"}]
      },
      "stressed": "столбца́",
      "status": "normal",
      "note": ""
    }],
    "diagnostics": []
  }],
  "diagnostics": []
}
```

В примере показана одна форма. Для «столбец» выдаются все 12 позиций парадигмы.
`reading_index` указывает на соответствующий элемент верхнего `readings`,
то есть разбора статьи. Наречие и числительное из «н; числ.» не смешиваются.

Схема **поля `generation`** — `schemas/generation.schema.json`. Схема анализа
по-прежнему описывает остальные поля без этого расширения.

Статусы генерации:

- `generated`: поддержанные разборы обработаны полностью;
- `partial`: часть разборов обработана, другие требуют реализации или заблокированы;
- `not_implemented`: отдельный механизм ещё не реализован;
- `blocked`: разбор не готов, отсутствует зависимость или обнаружена неподдержанная
  особенность внутри генерации.

У формы статус `normal`, `difficult`, `tentative` или `absent`. При `absent`
`word` и `stressed` равны `null`: выдуманное написание не выдаётся. Затруднительная
форма сохраняется с соответствующим статусом, а не заменяется отсутствием.
При пересечении ограничений действует более конкретное; ⌧ исключает мужскую
краткую форму, сохраняя затруднительные остальные краткие формы.

Разные допустимые написания и ударения возвращаются отдельными формами с
одинаковыми грамматическими признаками. Полные дубликаты удаляются. Регистр
сохраняется, включая имена с прописной буквы и слова целиком в верхнем регистре.

Код CLI в режиме генерации: 0 — все статьи `generated`; 1 — есть другой статус;
2 — ошибка документа, аргументов или ввода/вывода. Успешный `status: parsed`
верхнего уровня сам по себе не означает успешной генерации.

## Покрытие

- Существительные субстантивного склонения типов 0–8, род и одушевлённость,
  винительный падеж, беглые гласные, схемы ударения, отклонения ① и ②.
- Прилагательные адъективного склонения типов 0–5: полные и краткие формы,
  регулярная сравнительная степень, варианты кратких акцентных схем.
- Имена местоименного склонения по таблицам исходного генератора; в частности,
  `<мс 6*a>` на -ий. Для них краткие формы и сравнительная степень отсутствуют.
- Субстантивированные прилагательные и склонение по образцу другого рода:
  «столовая», «столище», «столяришка».
- Фамилии `<мс 1a>` на -ов/-ев/-ин: формы мужского и женского рода и множественное
  число. Особые окончания Р./Д./П. ед. учитываются также у притяжательных имён.
- Только множественное число при явно заданном образце. Единственное число
  в такой парадигме не создаётся.
- Особые чередования `°` в типах 1, 3, 8; явная помета `ё` для е/ё.
- Перечисленные формы местоимений и числительных, равенства падежей, варианты
  В. одуш.; наречия и другие уже разобранные неизменяемые разборы.
- Побочные ударения сохраняются в неизменившейся части основы. Если гласная с
  побочным ударением исчезает или изменяется предшествующая часть, требуется
  отдельное правило; программа блокирует разбор вместо потери ударения.

Сведения исходной статьи важнее внешнего сходства слов. Тип склонения не заменяет
неуказанное исключение: например, исходный индекс без текста нерегулярных форм
не является гарантией нормативности всех результатов. Сложные составные слова,
сложные условные исключения и часть дополнительных параграфов получают явную
диагностику. Поддержанные исключения, П2/Р2 и способы применения образца
описаны в [special.md](special.md).

## Спряжение

Вход остаётся тем же:

```json
{"lemma": "столби́ть", "symbol": "нсв", "grammar": "4b"}
```

Поддержаны типы 1–16, схемы личных форм `a`, `b`, `c`, `c′` и прошедшего
`a`, `b`, `c`, `c′`, `c″`; отсутствие второй схемы означает исходное правило `a`.
Переносятся согласные чередования, вставка беглого `о` в приставке `*`,
специальные чередования `°` в типах 3 и 6, явная помета `ё`,
отклонения ①–⑨ и факультативные варианты. Разные наборы отклонений имеют
отдельный кэш зависимых форм.

Выдаются:

- инфинитив: `form: infinitive`;
- личные формы: `form: finite`, `tense`, `number`, `person`;
- прошедшее: `form: finite`, `tense: past`, `number`, в единственном числе `gender`;
- императив: `form: imperative`, `number`, `person: 2`;
- деепричастия: `form: gerund`, `tense`; варианты на -в/-вши сохраняются;
- причастия: `form: participle`, `tense`, `voice`; полные формы дополнительно
  имеют `case`, `number`, при необходимости `gender` и `animacy`;
  краткие имеют `number` и при необходимости `gender`, без `case`.

Краткие действительные причастия помечаются `absent`. Сравнительная степень
для причастий не строится. Страдательные причастия ограничены переходностью,
возвратностью, видом и указанием видового партнёра; пометы `✕` и `⌧`
применяются к страдательным причастиям прошедшего времени. Помета `безл.`
оставляет инфинитив, 3 лицо единственного числа и прошедшее среднего рода
при допустимом времени; прочие позиции помечаются `absent`.

Как в исходнике, здесь строятся **простые словоформы**: настоящее несовершенного
и будущее совершенного вида, оба времени для двувидового. Составное будущее
«буду читать» не генерируется; соответствующие простые позиции несовершенного
вида имеют `absent`. Для настоящего совершенного действует такое же ограничение.

В типах 8 и 14 согласный инфинитивом однозначно не определяется: нужны, например,
`печь / 8b/b (-к-), ё` и `взя́ть / 14b/c (-м-)`. Без согласного образца результат
блокируется с `CONJUGATION_UNSUPPORTED`. Тот же статус получают несовместимые
окончания инфинитива, составные глаголы и неподдержанные схемы.

Видовое указание `◑` учитывается в ограничениях и позволяет построить новое слово
отдельно в `aspect_partner`. Его ошибка даёт общий статус `partial`, сохраняя
парадигму исходного глагола. Исключения, образцы, дополнительные параграфы
и границы их поддержки описаны в [special.md](special.md).

## Текущая пользовательская группа

Из 77 статей:

- для 75 построены именные, глагольные или явно описанные парадигмы;
- две отсылки заблокированы: в группе нет «затолочь» и «затолочься».

Результаты разбора до генерации остаются теми же: 75 `parsed`, две
`needs_reference`. Для всей группы CLI с `--generate` возвращает код 1 и
сохраняет все 77 результатов.

## Проверка и происхождение

Всего проходит 761 тест. Среди них — точное сравнение с оригиналом для
318 статей и 7059 позиций парадигм. Сравниваются написание, основное ударение
и статус формы. Выборка дополнена редкими акцентными схемами; охвачены все
восемь типов субстантивного склонения.

Это контроль переноса, а не доказательство нормативности каждого результата
оригинала или покрытия всех слов словаря. Отдельные языковые тесты проверяют
фамилии и притяжательные окончания, альтернативные и побочные ударения,
пустые/затруднительные формы, современную пользовательскую группу и Unicode.

Обычный запуск тестов не требует Perl, исходной базы или сети. Для независимого
пересоздания контрольного файла разработчик может выполнить:

```sh
python3 tools/build_declension_reference.py /путь/к/nlp-rus-zaliz
```

Нужен исходный коммит `5235199c09ab9e4443aeb7dd0b4d1be299cf80e8` и Perl.
Скрипт проверяет коммит и явно перезаписывает контрольный файл. Он запускает
оригинал, не импортируя Python-генератор. Из сравнительной выборки исключены
лексические исключения, которые проверяются отдельно,
и особые притяжательные окончания, неполно реализованные в оригинале.
Их тестирование не подменяется ожиданиями, рассчитанными самим новым движком.

### Проверка спряжения

Дополнительно сохранены 143 глагольные статьи и 21 307 позиций исходных правил.
Выборка включает все типы 1–16, все доступные в базе схемы ударений,
обязательные и факультативные отклонения, возвратность, вид, безличность и е/ё.
Сравниваются написание, позиция основного ударения, статус и помета варианта.

```sh
python3 tools/build_conjugation_reference.py /путь/к/nlp-rus-zaliz
```

Эталон строится без импорта Python-генератора. Для статей без факультативных
отклонений запускается исходная `wi2paradigm` без изменений. У оригинала
обнаружены два дефекта обхода факультативных веток: повторно используется кэш
причастия от первой ветки, а обязательные отклонения заменяются факультативными.
Например, у `передразни́ть / 4c[⑦]` теряется вариант `передразнённый`.
Эти дефекты в Python не воспроизводятся.

Для 11 статей с факультативными отклонениями контрольный Perl-скрипт готовит
каждую комбинацию заново через исходные `get_all_wi` и `inflect`, сохраняя
обязательные отклонения. Сам модуль оригинала не исправляется. В эталоне такие
статьи имеют `reference_mode: fresh_optional_branches`; исходный результат
`wi2paradigm` также сохраняется в `original_unmodified_result`. Таким образом,
полное совпадение с неизменённой `wi2paradigm` для этих веток не заявляется.

Независимые языковые тесты дополнительно проверяют «читаю», «люблю/любишь»,
«пеку/печёшь/пёк», «взял/взяла», «собью», «решён/решена», императив,
деепричастия, ограничения, Unicode, регистр и неизменность входной модели.
