# Генерация словоформ на Python

Реализованы разбор `lemma / symbol / grammar`, подготовка именных основ и
склонение существительных, прилагательных, имён местоименного склонения,
фамилий и явно выписанных форм. Реализовано спряжение типов 1–16:
личные формы, императив, причастия со склонением и деепричастия.
Добавлены выписанные исключения `△`, П2/Р2, перенос отсылочного образца
и построение видового партнёра. Покрытие дополнительных параграфов ограничено:
[исключения и образцы](docs/special.md).
Подробный формат результатов и границы покрытия: [docs/generation.md](docs/generation.md).

Требуется Python 3.10+. Рабочая программа использует только стандартную
библиотеку, не обращается к сети и не требует базы всех слов или Perl.

## Веб-прототип

Страница GitHub Pages принимает один JSON-объект или массив и запускает тот же
генератор в браузере через Pyodide. При первой загрузке браузеру нужен доступ
к CDN jsDelivr. Ввод обрабатывается в браузере. Страница показывает варианты,
диагностику и полный результат JSON.

Публикация выполняется workflow `.github/workflows/pages.yml` после отправки
в `main`. В настройках репозитория **Settings → Pages → Build and deployment**
нужно выбрать источник **GitHub Actions**. Адрес страницы после публикации:
`https://ilsuh.github.io/check_codex/`.

## Запуск

Из корня репозитория, без установки:

```sh
python3 -m zaliz --generate examples/single.json
python3 -m zaliz --generate examples/group.json -o forms.json
python3 -m zaliz --generate examples/special.json -o special-forms.json
python3 -m zaliz examples/group.json -o analysis.json
printf '%s\n' '{"lemma":"столбе́ц","symbol":"м","grammar":"5*b"}' | python3 -m zaliz
```

Для установки и запуска из любого каталога:

```sh
python3 -m pip install .
zaliz --generate descriptions.json -o forms.json
```

На вход принимается один объект или массив объектов, на выходе всегда массив
результатов в исходном порядке. Файл — UTF-8, допускается BOM. Без имени файла
или с аргументом `-` читается stdin. JSON Lines и внешние обёртки не принимаются.

Без `--generate` сохраняется прежний режим разбора. В этом режиме коды завершения:

- **0**: все статьи разобраны, все отсылки разрешены;
- **1**: JSON прочитан, но есть статьи с ошибками, неподдержанными указаниями
  или отсутствующими образцами; результаты доступны в выходном JSON;
- **2**: повреждённый JSON, ошибка структуры документа, аргументов или ввода/вывода.

Для `examples/group.json` ожидается код **1**: два образца в этой группе отсутствуют.
Файл результата при этом содержит все 77 статей, включая две диагностики.
С `--generate` код также 1: для 75 статей построены формы,
две требуют отсутствующих образцов.

## Python-интерфейс

```python
from zaliz import analyze, generate

results = analyze({"lemma": "столбе́ц", "symbol": "м", "grammar": "5*b"})
entry = results[0]
print(entry["status"])                              # parsed
print(entry["headword"]["text"])                    # столбец
print(entry["headword"]["accent_variants"][0]["primary"])  # [6]
print(entry["readings"][0]["inflection"]["index"])   # 5
```

`analyze` принимает `dict` или `list[dict]`, а не строку JSON. Для строки сначала
используйте `json.loads`. Ошибки структуры документа вызывают `zaliz.InputError`.
Ошибки конкретных статей сохраняются в результатах. Входные объекты не меняются;
контекст пустой леммы и отсылок не переносится между вызовами.

Для получения словоформ:

```python
forms = generate({"lemma": "столбе́ц", "symbol": "м", "grammar": "5*b"})[0]["generation"]["readings"][0]["forms"]
print([form["stressed"] for form in forms])  # столбе́ц, столбца́, столбцу́, ...
```

Статус анализа и статус генерации различаются. Отсутствующая форма имеет
`status: absent`, `word: null`; затруднительная сохраняет написание и
`status: difficult`. Варианты не теряются. В режиме генерации CLI возвращает 0,
только если все статьи имеют `generation.status: generated`.


## Что умеет парсер

- Сохраняет исходные данные и разбирает продолжения с пустой леммой.
- Различает HTML-теги и грамматические образцы `<п 1a>`, `<мс 6*a>`, `<с 4a[①]>`.
- Разделяет лексический род, род образца, часть речи и семейство склонения.
- Сохраняет альтернативные основные и побочные ударения, `ё`, `й`, регистр.
- Разбирает индексы, схемы ударения, звёздочки, кружочки, отклонения,
  согласные чередования, знаки `✕`, `⌧`, `~` и видовые указания `◑`.
- Отделяет толкования и примеры от грамматических указаний, сохраняет условия
  употребления и фразеологизмы как примечания.
- Представляет отдельные разборы наречия, числительного и местоимения.
- Восстанавливает выписанные формы со знаком `|`, окончаниями `-им` и т. п.,
  а также связи вида `В. одуш.=Р. или И.`.
- Разрешает отсылки к описаниям в этой же группе, включая ссылки вперёд;
  обнаруживает отсутствующие и неоднозначные образцы, цепочки и циклы.

Неизвестная грамматика сохраняется в `unparsed` и получает статус `unsupported`.
Сложные вложенные и условные исключения пока требуют расширения грамматики;
они не игнорируются. Распознанные, но неподдержанные номера `§` сохраняются
в модели и блокируют генерацию с объяснением.

Нормализация данных не означает проверки нормативности каждой возможной леммы
и не доказывает поддержку генерации для каждого распознанного индекса.
Разрешённая отсылка применяется при совместимой общей конечной части;
остальные способы переноса получают диагностику. В именных формах побочные ударения сохраняются в неизменившейся части основы;
неподдержанное перемещение диагностируется явно.

## Проверка

```sh
python3 -m pip install -r requirements-dev.txt
python3 -m unittest discover -s tests -q
```

Проходят **761 тест**: проверки парсера и его независимых эталонов,
318 статей / 7059 позиций склонения против оригинального Perl-генератора,
143 статьи / 21 307 позиций спряжения (факультативные ветки проверены отдельно),
языковые примеры, Unicode, ограничения, отсылки и оба режима CLI.
Дополнительно проверены 8 статей / 233 позиции с исключениями и П2,
60 видовых указаний; известные отличия от оригинала сохранены в эталоне
и объяснены в документации.
Проверяется также цепочка из 1200 отсылок.
Различия с кэшем факультативных причастий оригинала описаны в
[документации](docs/generation.md#проверка-спряжения).
`jsonschema` нужен только для тестов, не для работы программы.

Результат пользовательской группы: 77 статей, 79 грамматических разборов,
75 статей `parsed` и две `needs_reference` — для «столочь» и «столочься».
Их образцы «затолочь» и «затолочься» во входном массиве отсутствуют.
